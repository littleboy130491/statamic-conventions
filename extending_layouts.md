## Contextual Body Classes

The layout automatically adds **WordPress-style contextual classes** to the `<body>` element based on the current page context. This allows you to target specific pages, entries, or content types with CSS without adding classes manually.

### Automatic Classes Added

#### Homepage
```html
<body class="homepage locale-en ...">
```

#### Blog Entry
```html
<body class="entry entry-blog entry-id-123 slug-my-first-post template-post layout-layout locale-en ...">
```
- `entry` - All entries get this class
- `entry-blog` - The collection handle
- `entry-id-123` - The entry ID
- `slug-my-first-post` - The entry slug
- `template-post` - The template name
- `layout-layout` - The layout name
- `locale-en` - The site locale

#### Taxonomy Term Page
```html
<body class="term taxonomy-categories term-news template-taxonomy-term layout-layout locale-en ...">
```
- `term` - All taxonomy terms get this class
- `taxonomy-categories` - The taxonomy handle
- `term-news` - The term slug

#### Collection/Taxonomy Archive Pages

For listing pages (archives), Statamic doesn't provide a native detection variable. Instead:

**Option 1: Use template name**
```html
<body class="template-blog-index layout-layout locale-en ...">
```
Your template name becomes a class automatically.

**Option 2: Add custom class manually**
```antlers
{{# In your blog index template #}}
{{ section:body_class }}
archive archive-blog
{{ /section:body_class }}
```

**Result:**
```html
<body class="template-blog-index layout-layout locale-en archive archive-blog ...">
```

### Adding Custom Classes

Use `{{ section:body_class }}` to add your own classes on top of contextual classes:

```antlers
{{ section:body_class }}
featured-page has-sidebar
{{ /section:body_class }}
```

**Result:**
```html
<body class="entry entry-blog entry-id-123 slug-my-post template-post layout-layout locale-en featured-page has-sidebar bg-zinc-100 ...">
```

### Overriding Default Styles

Use `{{ section:body_style_class }}` to replace default styling classes while keeping contextual classes:

```antlers
{{ section:body_style_class }}
bg-white text-gray-900
{{ /section:body_style_class }}
```

### CSS Targeting Examples

Target specific collections:
```css
.entry-blog { /* All blog entries */ }
.entry-projects { /* All project entries */ }
```

Target specific entries:
```css
.entry-id-123 { /* Specific entry by ID */ }
.slug-about-us { /* Specific entry by slug */ }
```

Target the homepage:
```css
.homepage { /* Homepage only */ }
```

Target taxonomy archives:
```css
.taxonomy-categories { /* Category archive pages */ }
.term-news { /* Specific category */ }
```

Target by template:
```css
.template-post { /* All pages using post template */ }
.template-product { /* All pages using product template */ }
```

### Implementation

The contextual classes are generated by `resources/views/partials/contextual-body-classes.antlers.html`. You can customize this partial if you need different class patterns.

### CSS Examples

See `statamic-conventions/contextual-body-classes-examples.css` for extensive examples of using contextual body classes in your CSS, including:
- Targeting specific collections, entries, and taxonomies
- Combined selectors for complex targeting
- Responsive and dark mode variations
- Print styles based on content type

## Available Hooks

### Head Section

#### `{{ yield:styles }}`
**Purpose:** Add custom CSS styles
**Location:** Before closing `</head>`
**Usage:**
```antlers
{{ section:styles }}
<style>
    .custom-class { color: red; }
</style>
<link rel="stylesheet" href="custom.css">
{{ /section:styles }}
```

#### `{{ yield:head }}`
**Purpose:** Add any additional head content (fonts, preconnects, meta tags, etc.)
**Location:** Before closing `</head>`
**Usage:**
```antlers
{{ section:head }}
<link rel="preconnect" href="https://fonts.googleapis.com">
<meta name="custom" content="value">
{{ /section:head }}
```

---

### Body Section

#### `{{ yield:body_class }}`
**Purpose:** Add custom body classes (in addition to contextual classes)
**Location:** `<body>` element
**Contextual Classes:** Automatically added (WordPress-style):
- **Homepage:** `homepage`
- **Entry:** `entry entry-{collection} entry-id-{id} slug-{slug}`
- **Taxonomy Term:** `term taxonomy-{taxonomy} term-{slug}`
- **Template:** `template-{current_template}`
- **Layout:** `layout-{current_layout}`
- **Locale:** `locale-{site:short_locale}`

**Usage:**
```antlers
{{# Add custom classes on top of contextual classes #}}
{{ section:body_class }}
custom-page featured-content
{{ /section:body_class }}
```

**Result:** `<body class="entry entry-blog entry-id-123 slug-my-post template-blog layout-layout locale-en custom-page featured-content bg-zinc-100...">`

#### `{{ yield:body_style_class }}`
**Purpose:** Override default styling classes only (keeps contextual classes)
**Location:** `<body>` element
**Default Styles:** `bg-zinc-100 dark:bg-zinc-900 font-sans leading-normal text-zinc-800 dark:text-zinc-400`
**Usage:**
```antlers
{{# Replace default styling but keep contextual classes #}}
{{ section:body_style_class }}
bg-white text-gray-900
{{ /section:body_style_class }}
```

#### `{{ yield:body_attrs }}`
**Purpose:** Add custom attributes to body tag
**Location:** `<body>` element
**Usage:**
```antlers
{{ section:body_attrs }}
 data-page-type="landing" data-version="2"
{{ /section:body_attrs }}
```
**Note:** Include leading space in your content

#### `{{ yield:body_start }}`
**Purpose:** Add content immediately after `<body>` opens (analytics, GTM noscript, etc.)
**Location:** First thing inside `<body>`
**Usage:**
```antlers
{{ section:body_start }}
<!-- Google Tag Manager (noscript) -->
<noscript><iframe src="..."></iframe></noscript>
{{ /section:body_start }}
```

---

### Content Wrapper

#### `{{ yield:wrapper_class }}`
**Purpose:** Override wrapper div classes
**Location:** Main content wrapper `<div>`
**Default:** `mx-auto px-2 lg:min-h-screen flex flex-col items-center justify-center`
**Usage:**
```antlers
{{ section:wrapper_class }}
container mx-auto px-4 max-w-7xl
{{ /section:wrapper_class }}
```

---

### Content Sections

#### `{{ yield:before_content }}`
**Purpose:** Add header, navigation, or any content before main template
**Location:** Inside wrapper, before `{{ template_content }}`
**Usage:**
```antlers
{{ section:before_content }}
<header>
    {{ partial:navigation }}
</header>
{{ /section:before_content }}
```

#### `{{ template_content }}`
**Core:** Main template content renders here (not overridable)

#### `{{ yield:after_content }}`
**Purpose:** Add footer or any content after main template
**Location:** Inside wrapper, after `{{ template_content }}`
**Usage:**
```antlers
{{ section:after_content }}
<footer>
    {{ partial:footer }}
</footer>
{{ /section:after_content }}
```

---

### Scripts Section

#### `{{ yield:scripts }}`
**Purpose:** Add custom JavaScript
**Location:** Before closing `</body>`
**Usage:**
```antlers
{{ section:scripts }}
<script src="custom.js"></script>
<script src="another.js"></script>
<script>
    // Inline scripts
    console.log('Page loaded');
</script>
{{ /section:scripts }}
```

#### `{{ yield:body_end }}`
**Purpose:** Add content just before `</body>` closes
**Location:** Last thing before `</body>`
**Usage:**
```antlers
{{ section:body_end }}
<!-- Any final scripts or tracking -->
{{ /section:body_end }}
```

## How Sections Work

**Important:** Unlike Laravel's `@push`/`@stack` (which accumulates multiple pushes), Statamic's native `{{ section }}`/`{{ yield }}` works like `@section`/`@yield` - **the last section definition wins** (replacement, not accumulation).

### Example: Last Definition Wins

```antlers
{{# First section #}}
{{ section:scripts }}
<script src="app.js"></script>
{{ /section:scripts }}

{{# Second section - this REPLACES the first one #}}
{{ section:scripts }}
<script src="modal.js"></script>
{{ /section:scripts }}
```

**Result:** Only `modal.js` is included (last definition wins).

### Workaround: Combine in One Section

If you need multiple scripts, combine them in a single section:

```antlers
{{ section:scripts }}
<script src="app.js"></script>
<script src="modal.js"></script>
<script src="analytics.js"></script>
<script>
    // Inline code
</script>
{{ /section:scripts }}
```

### Alternative: Use Partials

For reusable components that need scripts:

```antlers
{{# In your partial: resources/views/partials/modal.antlers.html #}}
<div class="modal">...</div>

{{# In your template #}}
{{ section:before_content }}
{{ partial:modal }}
{{ /section:before_content }}

{{ section:scripts }}
{{# Include all scripts needed by partials and template #}}
<script src="/js/modal.js"></script>
<script src="/js/other.js"></script>
{{ /section:scripts }}
```

## Complete Example

Here's a comprehensive example showing how to extend the base layout and use all available hooks:

```antlers
{{#
    Extended template example
    File: resources/views/custom-page.antlers.html
#}}

{{# Add custom classes (contextual classes are auto-added) #}}
{{ section:body_class }}
custom-page featured-content
{{ /section:body_class }}

{{# Override default styling classes #}}
{{ section:body_style_class }}
bg-white text-gray-900
{{ /section:body_style_class }}

{{# Add custom body attributes #}}
{{ section:body_attrs }}
 data-page-type="example" data-component="custom"
{{ /section:body_attrs }}

{{# Override wrapper classes #}}
{{ section:wrapper_class }}
container mx-auto px-4 py-8 max-w-6xl
{{ /section:wrapper_class }}

{{# Add custom CSS #}}
{{ section:styles }}
<style>
    .custom-page {
        background: linear-gradient(to bottom, #fff, #f5f5f5);
    }
    .hero-section {
        padding: 4rem 0;
    }
</style>
<link rel="stylesheet" href="/css/custom-page.css">
{{ /section:styles }}

{{# Add additional head content #}}
{{ section:head }}
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap" rel="stylesheet">
{{ /section:head }}

{{# Add analytics or tag managers #}}
{{ section:body_start }}
<!-- Google Tag Manager (noscript) -->
<noscript>
    <iframe src="https://www.googletagmanager.com/ns.html?id=GTM-XXXXXX"
            height="0" width="0" style="display:none;visibility:hidden"></iframe>
</noscript>
{{ /section:body_start }}

{{# Add header/navigation #}}
{{ section:before_content }}
<header class="mb-8">
    <nav class="flex items-center justify-between py-4">
        <div class="logo">
            <a href="/">{{ site:name }}</a>
        </div>
        <ul class="flex gap-6">
            <li><a href="/">Home</a></li>
            <li><a href="/about">About</a></li>
            <li><a href="/contact">Contact</a></li>
        </ul>
    </nav>
</header>
{{ /section:before_content }}

{{# Main content area #}}
<main class="hero-section">
    <h1 class="text-4xl font-bold mb-4">{{ title }}</h1>

    {{ if subtitle }}
    <p class="text-xl text-gray-600 mb-8">{{ subtitle }}</p>
    {{ /if }}

    <div class="prose max-w-none">
        {{ content }}
    </div>

    {{ if features }}
    <div class="grid grid-cols-3 gap-6 mt-12">
        {{ features }}
        <div class="feature-card p-6 bg-white rounded-lg shadow">
            <h3 class="font-bold mb-2">{{ feature_title }}</h3>
            <p>{{ feature_description }}</p>
        </div>
        {{ /features }}
    </div>
    {{ /if }}
</main>

{{# Add footer #}}
{{ section:after_content }}
<footer class="mt-16 pt-8 border-t border-gray-200">
    <div class="flex justify-between items-center">
        <p class="text-gray-600">&copy; {{ now format="Y" }} {{ site:name }}. All rights reserved.</p>
        <div class="social-links flex gap-4">
            <a href="#" aria-label="Twitter">Twitter</a>
            <a href="#" aria-label="LinkedIn">LinkedIn</a>
        </div>
    </div>
</footer>
{{ /section:after_content }}

{{# Add custom JavaScript #}}
{{ section:scripts }}
<script src="/js/analytics.js"></script>
<script src="/js/feature-carousel.js"></script>
<script>
    // Initialize custom page functionality
    document.addEventListener('DOMContentLoaded', function() {
        console.log('Custom page loaded');

        // Example: Initialize feature carousel
        if (document.querySelector('.feature-card')) {
            initFeatureCarousel();
        }
    });
</script>
{{ /section:scripts }}
```

## Common Use Cases

### Simple Content Page

```antlers
{{ section:wrapper_class }}
container mx-auto px-4 py-8 max-w-4xl
{{ /section:wrapper_class }}

{{ section:before_content }}
<nav class="breadcrumbs mb-6">
    <a href="/">Home</a> / {{ title }}
</nav>
{{ /section:before_content }}

<article class="prose">
    <h1>{{ title }}</h1>
    {{ content }}
</article>

{{ section:after_content }}
<footer class="mt-8 text-center text-sm text-gray-600">
    &copy; {{ now format="Y" }}
</footer>
{{ /section:after_content }}
```

### Landing Page

```antlers
{{# Full-width, custom styling #}}
{{ section:body_class }}
bg-gradient-to-br from-blue-500 to-purple-600 text-white
{{ /section:body_class }}

{{ section:wrapper_class }}
w-full min-h-screen
{{ /section:wrapper_class }}

{{ section:styles }}
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap" rel="stylesheet">
<style>
    .hero { min-height: 100vh; display: flex; align-items: center; justify-content: center; }
    .cta-button { background: white; color: #6366f1; padding: 1rem 2rem; border-radius: 0.5rem; }
</style>
{{ /section:styles }}

{{ section:scripts }}
<script src="/js/landing-animations.js"></script>
<script>
    // Track landing page conversions
    gtag('event', 'page_view', { page_title: '{{ title }}' });
</script>
{{ /section:scripts }}

<div class="hero">
    <div class="text-center">
        <h1 class="text-6xl font-bold mb-4">{{ hero_title }}</h1>
        <p class="text-2xl mb-8">{{ hero_subtitle }}</p>
        <a href="{{ cta_link }}" class="cta-button">{{ cta_text }}</a>
    </div>
</div>
```

### Blog Post with Comments

```antlers
{{ section:wrapper_class }}

{{ /section:wrapper_class }}

{{ section:head }}
<meta property="article:published_time" content="{{ date format="c" }}">
<meta property="article:author" content="{{ author:name }}">

    {{ partial:site-navigation }}

    <div class="meta text-sm text-gray-600 mb-6">
        <span>By {{ author:name }}</span> |
        <time>{{ date format="F j, Y" }}</time>
    </div>

</article>

<section class="comments mt-12">
    <h2>Comments</h2>

</section>

{{ section:after_content }}
{{ partial:footer }}
{{ /section:after_content }}

<script src="/js/comments.js"></script>
{{ /section:scripts }}
```

## SEO Pro Integration

The base layout includes `{{ seo_pro:meta }}` which automatically generates:

- **Title tags** with fallbacks and customization
- **Meta description** for search results
- **Open Graph tags** (Facebook, LinkedIn) - og:title, og:description, og:image, og:url, og:locale
- **Twitter Card tags** - twitter:card, twitter:title, twitter:description, twitter:image
- **Canonical URLs** and alternate language links
- **JSON-LD structured data** for rich snippets
- **Site verification tags** (Google Search Console, Bing Webmaster Tools)
- **Robots meta tags** (noindex, nofollow control)

### Configuration

Configure SEO settings in:
- **Control Panel** > SEO Pro > Site Defaults
- **Entry Blueprints** - Add SEO field tab to your blueprints

### Per-Entry SEO Fields

Add this to your blueprint YAML to get SEO fields:

```yaml
-
  handle: seo
  field:
    type: seo_pro
    display: SEO
    localizable: true
```

This gives you entry-level control over:
- Title (with template preview)
- Description
- Open Graph image
- Canonical URL
- Robots indexing

## Tips & Best Practices

### 1. Don't Override Unless Needed
The defaults are sensible for most cases. Only override what you need to change.

### 2. Use Partials for Reusability
Keep your sections DRY by using partials:

```antlers
{{ section:before_content }}
{{ partial:header }}
{{ /section:before_content }}

{{ section:after_content }}
{{ partial:footer }}
{{ /section:after_content }}
```

### 3. Check SEO Output
View page source to ensure `{{ seo_pro:meta }}` is generating the expected meta tags.

### 4. Layer Templates
You can extend templates that extend other templates:

```
layout.antlers.html (base)
  └─ blog-layout.antlers.html (blog-specific wrapper)
      └─ blog-post.antlers.html (individual post)
```

### 5. Last Definition Wins
If you define the same section multiple times, only the last one is used. Combine everything in one section.

### 6. Combine Scripts/Styles
Since sections don't accumulate, put all your scripts/styles in a single section definition.

### 7. Leverage Contextual Body Classes
The layout automatically adds contextual classes (homepage, entry-{collection}, slug-{slug}, etc.). Use these in your CSS:

```css
/* Target specific collections */
.entry-blog .hero { background: blue; }
.entry-projects .hero { background: green; }

/* Target specific pages */
.slug-about-us { font-family: serif; }
.homepage .cta { display: block; }
```

### 8. Organize Section Definitions at Top
For readability, define all sections at the top of your template, then add your main content below.

## Need Stack/Push Functionality?

If you need true accumulation (multiple components adding scripts/styles independently like Laravel's `@push`/`@stack`), you have these options:

1. **Install the Stack addon**: https://statamic.com/addons/joe-tannenbaum/stack
   - Adds `{{ push }}`, `{{ prepend }}`, and `{{ stack }}` tags
   - Works exactly like Laravel Blade's stack system

2. **Use Laravel Blade**: Mix Blade templates with Antlers
   - Use `.blade.php` for layout with `@push`/`@stack`
   - Use `.antlers.html` for content templates
   - They work together seamlessly

3. **Organize in Single Section**: Manually combine all scripts in one place
   - This is the native approach
   - Works well for most sites where you control all sections

The native approach (using sections) works well for most sites where you control all the sections in your templates.
